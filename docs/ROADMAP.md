# ELUDA Roadmap

**Status:** Proposed sequence; dates and scope require owner approval

## Phase 0 — Establish project baseline
- [x] Create initial core documentation on the current feature branch.
- [ ] Review documentation with the product owner.
- [ ] Audit repository tree, current routes, branch history, assets and available tests.
- [ ] Verify preview deployment status and current behaviour.
- [ ] Record unknowns and blockers in `PROJECT_STATUS.md`.

## Phase 1 — Product definition
- [ ] Validate target users and primary use cases.
- [ ] Approve MVP boundaries and success criteria.
- [ ] Approve core user journeys and screen inventory.
- [ ] Decide required privacy and safety behaviour.

## Phase 2 — UI/UX system
- [ ] Approve brand direction, palette, typography and components.
- [ ] Design every MVP screen and relevant system state.
- [ ] Review mobile and desktop layouts.
- [ ] Complete accessibility and interaction review.
- [ ] Obtain explicit design approval before feature implementation.

## Phase 3 — Architecture and implementation readiness
- [ ] Audit existing technical implementation.
- [ ] Approve frontend/backend/database/authentication/storage decisions.
- [ ] Define data model, API contracts and security requirements.
- [ ] Define testing strategy, environments and release criteria.

## Phase 4 — MVP implementation
Tasks to be prioritised only after Phase 3 approval. Implement in small, testable changes on feature branches; maintain status and task evidence.

## Phase 5 — Launch readiness
- [ ] Functional and regression testing.
- [ ] Privacy, security and abuse-case review.
- [ ] Mobile, desktop and accessibility checks.
- [ ] Operational moderation and support process ready.
- [ ] Legal/privacy obligations assessed.
- [ ] Owner approves release.

No launch date is committed by this roadmap.
